## 2026-10-26: Context-owned bounded search records

Separated A* record admission/lookup/recycling from the permanent unit/obstacle
pool. Experimental searches use a fixed-capacity keyed pool owned by the context;
no search record is assigned to cell m_info. Each record names its owning stamped
arena, so different contexts cannot alias costs or parents. Persistent cells get
private shadow scratch without consuming extra transient admission credit. Keep
30,000 slots, stable heap ordering and original per-request queue scheduling.
Permanent allocation and recycling no longer reset active search state. Search
cleanup touches only private records; map/generation reset discards unreachable
scratch. Default builds route search helpers through their existing cell records.

The explicit bound is permanent records plus charged transient search cells <=
30,000 at admission, and at most 30,000 shadow/search records per context. Reclaiming
old scratch at a generation boundary can change exhaustion outcomes versus legacy
orphan retention; replay equivalence is not established. The local 64-bit fixture
uses approximately 3.4 MiB more fixed storage than the preceding stage. Added
collision/churn/rollover, full occupancy, pool reuse, independent owner and actual
cell/list route-order checks. Workers remain disabled; request/result isolation and
live engine dependencies still need work before concurrency.
Validation: 64 workflow QA tests passed locally; all 17 context/allocation tests
passed AddressSanitizer and UndefinedBehaviorSanitizer. Actionlint and diff checks
passed. Full iOS SDK compilation and device/replay verification remain pending.
