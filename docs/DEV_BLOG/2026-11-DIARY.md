## 2026-11-01: Carry memory requests in the externally signed game IPA

The user clarified that Generals is installed directly, so earlier inspection of
LiveContainer's profile/signature did not establish anything about the game.
The unsigned game packager removed every Mach-O signature and exported memory
requests only as a separate plist. SideSign intersects profile permissions with
requests read from the executable, allowing the installed game to lose a key
even when a provisioning profile permits it.

After removing stale signatures/profiles, ad-hoc sign only the game executable
with the existing memory requests. Extract and compare the embedded dictionary
before creating the IPA; fail packaging on signing or request-retention failure.
Keep external Apple signing mandatory and export the inspected request alongside
the source plist. Preserve gameplay, native signed builds and dependency signing.

All twelve packaging control-flow fixtures pass, including request preservation,
removal order and hard failures. Shell parsing and whitespace checks pass. The
fixtures simulate signing; real Mach-O extraction runs in the native macOS build. Device grant and running-process verification
remain pending. Document full Generals import/signing rather than profile-only
refresh, and distinguish the custom SideStore memory fix from EVA enablement.
